# 003. key 기반 자식 재정렬

- 상태: Accepted
- 날짜: 2026-11-07

## 맥락

Diff의 기본 케이스는 다섯 가지다.

1. 노드 추가
2. 노드 삭제
3. 태그가 다르면 하위 트리 교체
4. 속성 변경
5. 텍스트 변경

자식을 위치끼리만 비교하면 `[A, B, C]`가 `[C, A, B]`로 바뀌었을 때 세 노드를 모두 변경으로 본다. 입력 중인 `<input>`이 섞여 있으면 값이 다른 줄로 옮겨 가는 문제도 생긴다.

## 결정

- 자식에 key가 있으면 key로 이전 노드와 짝을 찾는다. 짝이 있으면 노드를 재사용해 이동시키고, 짝이 없으면 추가·삭제한다.
- key가 없으면 위치(인덱스)끼리 비교한다.
- Phase 1 테스트 영역에서는 HTML 속성 `data-key`를 key로 읽는다. Phase 2에서는 VNode의 `key`를 쓴다.

## 결과

- 목록 재정렬 시 DOM 생성·삭제 대신 이동만 일어나고, 노드 상태가 보존된다.
- 이동 연산과 key 매칭 로직이 추가되어 diff가 복잡해진다.
- 같은 부모 아래 key가 중복되면 결과를 보장하지 않으므로 경고를 낸다.
